# FinGrow — Antigravity Build Pack

## Start here
1. Extract this folder into the root of a clean Git repository (or copy its contents into the existing repository).
2. Open the repository in Google Antigravity.
3. Read `MASTER_PROMPT.md` and submit it to the primary/orchestrator agent.
4. Ask the orchestrator to read every project instruction file before changing code.
5. Let the orchestrator inspect the repository and produce the architecture, agent plan, dependency graph and task ownership before parallel implementation begins.
6. Approve the proposed stack and any external services before credentials, paid resources or production infrastructure are used.

## Included instructions
- `MASTER_PROMPT.md` — project-wide build mandate and acceptance criteria.
- `AGENT_ORCHESTRATION.md` — parallel agent strategy, ownership, integration rules.
- `PRODUCT_REQUIREMENTS.md` — audience, journeys and product modules.
- `DESIGN_SYSTEM.md` — visual direction, colors, typography and UX rules.
- `ARCHITECTURE.md` — modular architecture, service isolation and extensibility.
- `DATA_AND_API_CONTRACTS.md` — domain boundaries, API and event contracts.
- `SECURITY_PRIVACY.md` — security, privacy, moderation and financial-simulation safeguards.
- `SEO_ACCESSIBILITY.md` — technical SEO, content SEO, accessibility and performance.
- `TESTING_AND_QA.md` — test strategy and definition of done.
- `DELIVERY_AND_DEPLOYMENT.md` — environments, CI/CD, observability and release safety.
- `CHANGE_MANAGEMENT.md` — safe future feature and workflow changes.
- `agents/` — specialist agent briefs.

## Important operating rule
“Use as many agents as possible” means use the maximum useful parallelism supported by the installed Antigravity environment, not unlimited agents working on the same files. Parallelize independent work, assign exclusive ownership, and integrate through agreed contracts. Do not create merge conflicts or duplicate implementations just to increase agent count.

## Product safety
FinGrow is an educational platform. All investment and business simulations must use clearly labelled virtual money and fictional or appropriately licensed/delayed data. Do not place real trades, collect brokerage credentials, promise returns or provide personalized investment recommendations.
